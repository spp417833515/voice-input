01 / Executive Summary

先给决策者的三句话

对方代理的方向是对的，但实现路径不完整。这个项目需要的不是“再修一次快捷键”，而是把按键从“旁听事件”升级为“所有权资源”。

对方说对了什么

Wayland 下桌面是唯一能按单键独占的地方；Ctrl+Alt+D 与 show-desktop 冲突；Ctrl+Shift+Z 与 redo 冲突；grim/slurp 在 GNOME 上不成立。

对方方案缺什么

GNOME 自定义快捷键没有松开事件，语音按住说话会变成“只能开不能停”；只走门户会漏掉旧 KVM/XTEST；也没有回答“保留原键位就要失去 show-desktop/redo”的取舍。

本方案怎么改

Wayland 用 portal GlobalShortcuts，X11 用 XGrabKey，旧 XTEST 用 XI2 observer 兜底；截图走 portal Screenshot + 自绘冻结选区；动作收敛到一个共享动作层（ActionMixin + Manager）。

三个不能接受的“伪修复”

只改键位，不改通道

按键仍会穿透到应用；换一个应用又可能冲突。键位是必要条件，不是充分条件。

只接 portal，不留 XTEST 兜底

旧 KVM / Synergy XTEST 注入根本到不了 compositor，热键会全死。

只修 grim/slurp 安装

GNOME 没有 wlr-screencopy / wlr-layer-shell，装多少遍都没用。

本报告为设计基线；实现已按方案进行，代码改动见 git diff。方案正文见 docs/plans/hotkey-root-fix.md。

04 / Root Cause

三条根因链，而不是三个补丁

如果把这三条链任何一条当成“单个 bug”，修出来的都会是补丁：换键位会复发、装 grim 会继续失败、加一个后端会继续复制动作代码。

RC-1 · 所有权缺失

为什么 Ctrl+Alt+D 会收起窗口？
GNOME 的 show-desktop 绑定包含 Ctrl+Alt+D。
为什么 daemon 也同时响应？
daemon 只旁听、不消费按键；GNOME 收到的同时它也收到。
为什么只旁听？
Wayland 下 XI2 raw 不是全局 grab，XGrabKey 也抓不到全局键。
为什么还在用 XI2？
没有 compositor 级快捷键后端，只有 X11 时代的 XGrabKey 和后来的 fallback。
为什么一直没暴露？
BadAccess 被吞掉；启动没有冲突扫描；测试只覆盖 happy path。
根因：daemon 没有“谁拥有这个键”的概念。

RC-2 · 能力探测缺失

为什么 GNOME 上截不到图？
grim 缺 wlr-screencopy，slurp 缺 wlr-layer-shell。
为什么还选它？
detect_screenshot_tool() 只看 shutil.which，不看 compositor。
为什么假设 wlroots？
Wayland 支持是按 wlroots 工具链做的，没有 GNOME 能力分支。
为什么用户没看到错误？
非零退出把状态改回“就绪”，stderr 被 DEVNULL。
为什么没有兜底？
maim 在 XWayland 全黑；gnome-screenshot 未装；没有 portal 路径。
根因：截图后端按“名字”匹配，不按“能力”匹配。

RC-3 · 动作层耦合

为什么三个 grabber 都有一份录音/截图/重复逻辑？
每次加 fallback 都是复制上一个类再改。
为什么复制？
没有独立的共享动作层。
为什么这会让冲突难修？
松开语义、自动重复、修饰键清理、浮层关闭分散在三个类里。
为什么现在必须重构？
portal 有原生 Activated/Deactivated；硬塞进旧契约只会继续长分支。
根因：输入后端与业务动作没有分层。

横切根因：失败不可见

XGrabKey 的 BadAccess 被吞、截图非零退出回“就绪”、启动只说“启用了哪个类”却不说“能不能真正全局”。用户只能通过“窗口突然收起”反推。设计原则：fail loud——拿不到键、截不到图、门户被拒、后端降级，都必须出现在启动报告和状态栏。

为什么其他代理的“登记成 GNOME 快捷键”不能照抄

没有松开事件

GNOME 自定义快捷键按下执行命令，没有 Deactivated。语音是按住说话，照抄会变成“只能开始、无法停止”。正确 API 是 portal GlobalShortcuts。

漏掉 XTEST 旧路径

compositor 看不到 XTest 注入。portal 不可用时必须留 observer 兜底；portal 可用时 XWayland 源合并，不能承诺 XTEST-only 注入。

06 / Target Architecture

目标架构：一层所有权，一层仲裁，一层动作

on_trigger():
    gen = ++generation
    png = portal_screenshot()          # interactive=false, 整屏
    overlay = SelectionOverlay(png)    # 冻结画面 + 自绘矩形
    rect = overlay.wait_selection()
    if gen != generation or rect is None:
        return
    crop = png.crop(rect * scale)      # 逻辑坐标 -> 图像像素
    text = POST("/api/ocr_translate", crop)
    if gen == generation:
        TranslationOverlay.show(rect, text)

冲突检测

Wayland

扫描 wm/shell/media-keys/mutter + 自定义 keybindings；归一化 accelerator；给出冲突键路径。

X11

瞬时 XGrabKey 探测 BadAccess，探测后立即 ungrab；不周期性盲抓。

应用级

无法枚举所有应用。portal 会消费绑定键，所以请选一个你不需要在应用里用的组合；设置页给出提示。

07 / Benefits

收益：从“能用”到“可解释”

冲突归零

选定键位后，桌面/应用不再和 daemon 同时收到同一动作。

当前输入源覆盖
