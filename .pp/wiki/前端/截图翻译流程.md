# 截图翻译流程

## 一句话定位

Wayland 下不再调用 grim/slurp/maim：先建一个 2x2 透明焦点窗口满足 GNOME 门户的访问对话框要求，向 `xdg-desktop-portal` 要一张整屏图，再在冻结图上自绘选区、按像素精确裁剪，最后复用现有 OCR/翻译浮层。X11 仍保留 maim 选区路径。

## 关联代码路径

- `daemon.py` `detect_screenshot_tool()` — Wayland 只认 `org.freedesktop.portal.Screenshot`；X11 用 maim/gnome-screenshot。
- `daemon.py` `screenshot_translate()` — 入口；portal 分支 / X11 maim 分支。
- `daemon.py` `_portal_screenshot_translate()` — generation token、取消旧选区、启动 portal 截图。
- `daemon.py` `_register_portal_host_app()` — Screenshot 前同样需要 host app app_id（systemd 服务无桌面上下文）。
- `daemon.py` `PortalScreenshotClient` — D-Bus Screenshot 请求、Response、30s 超时、URI → 临时 PNG。
- `daemon.py` `_open_portal_parent_window()` — 2x2 透明 `parent_window`；GNOME 50 要求调用者处于焦点。
- `daemon.py` `SelectionOverlay` — 冻结整屏、拖选、Esc/右键取消、`_selection_crop_box`。
- `daemon.py` `_on_selection_done()` / `_portal_ocr_request()` — 裁剪 + OCR + 结果浮层。
- `daemon.py` `TranslationOverlay` — 结果浮窗（选区原位、任意键/点击外部关闭）。
- `daemon.py` `_do_screenshot_translate()` — X11 maim 的旧链路。
- `app.py` `/api/ocr_translate` — OCR + 翻译 API。

## 功能节点说明

### Wayland portal 路径

1. `screenshot_translate()` 分配 `gen = ++_screenshot_generation`，关闭旧选区/结果浮层，取消旧 portal client。
2. `detect_screenshot_tool()` 返回 `portal`（`Screenshot` 接口存在且版本 ≥1）。
3. 确认 host app 已注册（`org.freedesktop.host.portal.Registry`）；否则 systemd 服务下门户报 `An app id is required`。
4. 创建 2x2 透明 GTK 窗口并 `present()`，等待 map 后取 XID，传 `parent_window=x11:0x...`。
5. `PortalScreenshotClient.Screenshot(parent_window, {interactive:false, modal:true})`：
   - 异步 `Response`；`response != 0` → 用户取消/门户拒绝；
   - 返回 `uri`（GNOME 50 会写到 `~/图片/Screenshot-N.png`）；
   - 复制到 `/tmp/...png`，删除 portal 源文件；
   - 30s 超时。
6. `SelectionOverlay`：
   - 按当前指针所在显示器取 monitor，冻结图裁剪出该屏；
   - 全屏无边框窗口，`fullscreen_on_monitor`；
   - 拖拽矩形、`Esc`/右键取消、`<5px` 视为取消；
   - 选中后先销毁自身，再回调，释放焦点/事件。
7. `_on_selection_done()`：
   - `gen` 过期则丢弃临时文件；
   - 立即显示加载浮层（选区原位）；
   - 后台线程用 PIL 按 `_selection_crop_box()` 裁剪；
   - `POST /api/ocr_translate`；
   - 成功后 `TranslationOverlay.show_result`；失败显示错误。
8. 连按：新触发递增 generation，旧响应/旧裁剪结果被丢弃；旧选区被静默关闭，不触发旧取消回调。
9. 选区 30s 无操作自动取消，避免全屏窗口永久停留。

### 几何与 DPI

- 图像坐标 = 屏幕逻辑坐标 × `图像尺寸 / Gdk.Screen 逻辑尺寸`。
- monitor 子图偏移记为 `_mon_img_x/_mon_img_y`；选区矩形先乘 `_sel_scale_x/_sel_scale_y`，得到 PIL `(left, top, right, bottom)`。
- 单屏 3840×2160 已实测：拖 400×200 → 裁剪 400×200。
- 多屏：当前按指针所在 monitor 逐屏处理；跨屏拖选暂不支持（后续可按需加每屏窗口/Shell 扩展）。

### X11 maim 路径

- `maim -s` 选区；后台线程等待进程。
- 结果浮层位置仍用“鼠标释放点 − 图片尺寸”反推（X11 旧逻辑）；失败时显示“截图已取消/失败”，不再静默回“就绪”。
- `maim` 在 Wayland/XWayland 下会全黑，因此 Wayland 不选它。

## 失败与清理

- 门户拒绝/无焦点：`截图失败: ...` + 状态栏；不再静默。
- 超时：30s 后失败；父窗口/临时文件清理。
- 取消：删除临时 PNG，状态“已取消”。
- 翻译引擎全挂（Google/百度/MyMemory 都是外部网络）：API 返回 200 + OCR 原文 + `warning`；daemon 显示原文并标记“翻译失败，已显示原文”，不让整个截图流程 502。
- 进程退出：`_panic_release_all` 关闭 portal 父窗口/选区窗口；`_screenshot_client.cleanup()` 清理挂起请求。
- 截图失败不会影响剪贴板/输入链路。
