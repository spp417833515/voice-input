# 截图翻译流程

## 一句话定位

热键触发后主线程立刻启 maim/grim/gnome-screenshot 选区，后台线程等截图完成 → 在选区原位置弹一个加载状态的 GTK 浮窗 → POST 给 `/api/ocr_translate` → 用结果替换浮窗内容；支持 Esc/外部点击/30s 自动关闭。

## 关联代码路径

- `daemon.py:1497-1498` `_screenshot_proc / _screenshot_lock` — 跨触发的进程共享句柄
- `daemon.py:1501-1544` `screenshot_translate()` — 主线程入口：取消旧进程、选工具、立即启 Popen、分派后台线程
- `daemon.py:1547-1604` `_do_screenshot_translate(proc, tmp_path)` — 后台主逻辑
- `daemon.py:1069-1301` `class TranslationOverlay(Gtk.Window)` — 透明浮窗，含加载脉冲、复制按钮、pointer grab 检测外部点击、30s 自动关闭
- `daemon.py:1304-1314` `_show_overlay_loading(x,y,w,h)` — GTK 主线程槽，创建新覆盖层（销毁旧的）
- `daemon.py:1317-1321` `_update_overlay_result(text, is_error)` — GTK 主线程槽，切换 loading→结果
- 调用方：`HotkeyGrabber._handle_event` (daemon.py:1719)、`XInputHotkeyGrabber._handle_press` (daemon.py:1928)、evdev grabber 同等位置

## 功能节点说明

- 并发设计：每次触发立即 terminate 上一个仍在运行的 maim/grim 进程，再启新的 —— 用户连按截图键不会被前次 hold（daemon.py:1508-1515 第一性原理注释）。
- 工具探测 `detect_screenshot_tool()`：返回 `x11-maim` / `wayland-grim` / `gnome` 三种之一（或 None）；对应命令 `maim -s` / `grim -g "$(slurp)" file` / `gnome-screenshot -a -f file`。
- 选区原位定位：用图片宽高反推 —— 鼠标释放点视为选区右下角，所以 `sel_x = mouse - img_w`, `sel_y = mouse - img_h`；取不到鼠标位置时降级到 (100,100)。
- 浮窗交互（TranslationOverlay）：
  - `pointer grab`（`seat.grab` daemon.py:1159-1167）+ 100ms 轮询 `_check_outside_click`（daemon.py:1176-1200）双保险检测窗口外点击。
  - 复制按钮例外（`_on_window_click` daemon.py:1207-1222）：点中按钮区不关闭。
  - 加载阶段 `Gtk.ProgressBar.pulse()` 每 100ms。
  - 30s 自动 `_auto_close`；销毁时 `seat.ungrab` 释放 pointer。
- HTTP 失败处理：异常时浮窗显示 `失败: <前40字>` 红色样式。

## 关联复用

- 无 L5 复用单元被本模块独占调用（TranslationOverlay 是本模块专属类）。
