# 全局快捷键系统

## 一句话定位

daemon 启动时按 `XInput2 raw → evdev → XGrabKey` 顺序构造三种 grabber，第一个不抛异常的胜出；三者共享 `voice_active / start / cleanup / grab / ungrab` 接口契约，并通过 50ms 延迟释放抑制 X11 自动重复事件造成的伪释放。

## 关联代码路径

- `daemon.py:2399-2415` `main()` 三级 fallback 选择 grabber
- `daemon.py:1630-1773` `HotkeyGrabber` — XGrabKey 经典 server-side grab + GLib.io_add_watch
- `daemon.py:1797-1986` `XInputHotkeyGrabber` — XInput2 RawKey 被动监听（拦 SendEvent/KVM 注入，**当前主路径**）
- `daemon.py:1994-2200+` `EvdevHotkeyGrabber` — 内核级 `/dev/input/event*`，Wayland 兼容
- `daemon.py:250-276` `_parse_hotkey` — 给 XInput/XGrabKey 用的 X11 mask+keysym 解析
- `daemon.py:291-337` `_parse_hotkey_evdev` — 给 evdev 用的 keycode 解析
- `daemon.py:1622-1627` `LOCK_MASKS` — NumLock/CapsLock 组合的 4 倍 grab
- `daemon.py:40-42` 配置常量：`HOTKEY_VOICE / HOTKEY_SCREENSHOT / HOTKEY_REPEAT`

## 功能节点说明

- 接口契约：三个 grabber 都暴露 `__init__(recorder) / start() / cleanup() / grab() / ungrab() / voice_active: bool`。XInput2 的 `grab/ungrab` 是 no-op（XInput2 raw 是被动 stream，不需要 server-side grab）。
- `_voice_combo / _screen_combo / _repeat_combo`：XInput 版本是 `{trigger: keycode, modifiers: [set, ...]}`；evdev 版本同结构但来自不同解析函数；XGrabKey 版本是 `(keycode, mask)` 二元组。
- 自动重复抑制：KeyRelease 不立即触发 stop，挂 50ms `GLib.timeout_add(50, self._do_release)`；若 50ms 内同键再次 KeyPress（自动重复），取消该定时器。
- XGrabKey 路径下额外有 `_refresh_grab` 500ms 周期幂等 re-grab，应对某些 WM 偶尔丢 grab 的情况（daemon.py:1700-1706）。
- XInput2 路径下 `_pressed` 只做自动重复与录音抬起；`_match_combo(combo, pressed_kc)` 要求 **当前按下的键就是 trigger**，修饰键用 `query_keymap`（拒绝幽灵卡键）。
- 注入回流：`_on_xlib_event` 丢掉 sourceid 属于 `ollama-voice-input` 的 raw 事件。不能按 XTEST 过滤（Synergy 的键盘是 XTEST）。找不到该设备时，才用 `_inject_until` 时间窗回退（release 仍放行三个 trigger）。
