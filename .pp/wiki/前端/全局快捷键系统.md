# 全局快捷键系统

## 一句话定位

Wayland 下由 **xdg-desktop-portal GlobalShortcuts** 让 GNOME compositor 独占按键，X11 下用 **XGrabKey** 独占；evdev / XInput2 观察器只负责键盘活动与 portal 不可用时的兜底。三种后端共享 `HotkeyActionMixin` 的录音/截图/重复逻辑，`HotkeyManager` 负责选择、降级与 watchdog 代理。

## 关联代码路径

- `daemon.py` `HotkeyManager` — 按会话选择所有权后端；portal 可用时启动观察器 + portal；失败时启用 evdev/XI2 回退。
- `daemon.py` `PortalGlobalShortcutsGrabber` — D-Bus `org.freedesktop.portal.GlobalShortcuts`；`Host Registry → CreateSession → BindShortcuts → Activated/Deactivated`。
- `daemon.py` `_register_portal_host_app` — `org.freedesktop.host.portal.Registry.Register(app_id, {desktop_entry})`；systemd 服务没有桌面上下文，必须先注册，否则门户报 `An app id is required`。
- `daemon.py` `HotkeyActionMixin` — 共享 `_on_voice_press / _do_release / _on_repeat / _do_repeat`，不再由每个 grabber 复制。
- `daemon.py` `HotkeyGrabber` — X11 `XGrabKey`；`grab()` 后 `sync()` 收集 BadAccess 并显式告警。
- `daemon.py` `XInputHotkeyGrabber` — XInput2 raw 观察器；`only_xtest_sources` 为旧 XTEST 最佳努力开关。
- `daemon.py` `EvdevHotkeyGrabber` — 内核级键盘观察/回退；按设备名过滤自身 uinput。
- `daemon.py` `scan_hotkey_conflicts()` — 扫描 GNOME 桌面级快捷键（wm/shell/media-keys/mutter + 自定义 keybindings）。
- `daemon.py` `_to_portal_trigger()` / `_format_hotkey()` / `_normalize_accel()` — portal trigger、显示、冲突归一化。

## 功能节点说明

### Wayland 主路径

1. `HotkeyManager.start()` 先启动 Evdev 与 XInput 观察器，`actions_enabled=False`。
2. `PortalGlobalShortcutsGrabber` 初始化时先调用 **host app registry** 注册 `app_id` 与 `desktop_entry`；systemd 服务没有桌面上下文，不注册会被门户拒绝。
3. `PortalGlobalShortcutsGrabber.start()` 通过 D-Bus 创建 session 并 `BindShortcuts`，绑定：
   - `voice` — `HOTKEY_VOICE`
   - `screenshot` — `HOTKEY_SCREENSHOT`
   - `repeat` — `HOTKEY_REPEAT`
4. compositor 独占按键；`Activated(id)` 走对应动作，`Deactivated(voice)` 停止录音。
5. 门户返回的 `trigger_description`（如 `按 <Control><Alt>z`）记录到 `actual_triggers`，仅用于显示/诊断；动作映射以 shortcut id 为准。
6. 退出时 `Session.Close()`；失败时 `HotkeyManager` 清理 portal 并启用观察器回退。

### systemd 运行注意

- 服务单元直接 `exec python`，**不要**用 `sg input`/setgid：setgid 会让进程不可 dumpable，portal 无法打开 `/proc/PID/root`。
- 用户组由 systemd user manager 继承；用户需在 `input` 组（install.sh 检查）。
- daemon 专用 `.desktop`（`ollama-voice-input-daemon.desktop`）供 Host Registry 使用；install.sh 生成。

### X11 主路径

- `HotkeyGrabber.grab()` 注册三组键 + NumLock/CapsLock 变体。
- `sync()` 后若收到 X error（典型 BadAccess），打印 `XGrabKey 冲突/错误`，不再静默吞掉。
- `KeyRelease` 仍使用 50ms 延迟释放抑制自动重复。

### 观察器与回退

- portal 可用：观察器 `actions_enabled=False`，只负责：
  - 关闭结果浮层（任意键）；
  - 卡键检测（XInput `has_stuck_modifiers`）；
  - 自身 uinput 回流过滤。
- portal 失败/不可用：
  - 有 Evdev：Evdev 触发动作，XInput 仅 XTEST 最佳努力；
  - 只有 XInput：XInput 接管它能看到的按键；
  - 启动日志必须明确“按键未独占，可能仍会传给应用”。
- **已知限制**：XWayland 常把物理键与 XTEST 都归到 `xwayland-keyboard:*`，source-level 不可靠；portal 可用时不承诺旧 XTEST-only 注入可用。

### 动作语义

- `_on_voice_press()`：幂等；`recorder.start()` 失败则回滚 `voice_active`。
- `_do_release()`：停止录音；`_release_modifiers_on_stop=True` 的后端才补发修饰键释放；portal 后端为 `False`。
- `_on_repeat()`：无历史结果时提示；否则后台线程执行重复输入。
- `screenshot_translate()`：portal 截图 / X11 maim 分支，见 `前端/截图翻译流程.md`。
- `HotkeyManager.voice_active` 汇总所有后端状态，watchdog/状态栏只依赖该属性。

### 冲突扫描

- `gsettings list-recursively` 扫描：
  - `org.gnome.desktop.wm.keybindings`
  - `org.gnome.shell.keybindings`
  - `org.gnome.settings-daemon.plugins.media-keys`
  - `org.gnome.mutter.keybindings`
  - `org.gnome.mutter.wayland.keybindings`
  - 自定义 keybindings
- `_normalize_accel("<Primary><Alt>d") → "ctrl+alt+d"`，与 `HOTKEY_*` 比较。
- 应用级快捷键（如编辑器 redo）无法枚举；通过更换默认键与文档提示规避。
- 结果进入 `startup_check()` 的“配置检查”，启动时显式打印。
